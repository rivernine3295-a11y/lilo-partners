# 체어그로스 디자인 전면 개편 프롬프트 (릴로 홈페이지 디자인 방향 기준)

아래 전체를 그대로 복사해서 체어그로스 작업 창에 붙여넣으세요.

---

## 역할과 목표
당신은 체어그로스(SaaS)의 프런트엔드 디자인 개발자입니다. 릴로 홈페이지(lillo.kr)에서 완성한 **"어두운 영화 같은 화면 + 보라 그라데이션 포인트 + 떠 있는 알약 내비게이션"** 디자인 언어를 체어그로스에 적용해 더 고급스럽게 바꾸는 것이 목표입니다.
기능, 데이터, API, 계산 로직, 문구의 의미는 바꾸지 않습니다. **겉모습(스타일, 배치, 움직임)만** 바꿉니다.

## 0. 작업 방식 (가장 중요)
1. **먼저 조사만 하세요.** 체어그로스의 화면 목록, 공통 스타일 파일, 컴포넌트 구조, 지금 쓰는 색·폰트를 파악해서 표로 보고하세요. 아직 코드는 바꾸지 마세요.
2. **적용 계획을 제안하세요.** 화면 유형별로 어디까지 바꿀지(아래 8번 참고), 손댈 파일, 예상 위험을 정리해 제가 승인한 뒤에 시작하세요.
3. **한 화면씩 바꾸세요.** 한 번에 전부 교체하지 마세요. 먼저 공통 토큰과 공통 컴포넌트를 바꾸고, 그 다음 화면을 하나씩 옮기세요.
4. 화면 하나를 바꿀 때마다 **스크린샷(휴대폰 390px, 컴퓨터 1280px, 전체 페이지)**으로 확인하고, 기존 기능이 그대로 되는지(버튼, 폼, 로그인, 결과 표시) 직접 눌러서 확인하세요.
5. **스타일을 한꺼번에 교체할 때는 지우는 범위를 정확히 확인하세요.** 범위를 잘못 잡아 중간 스타일이 통째로 사라진 사고가 있었습니다. 교체 뒤에는 바뀐 줄을 비교(diff)해서 의도한 부분만 바뀌었는지 반드시 보세요. 화면 맨 위만 캡처하지 말고 **끝까지 스크롤한 전체**를 보세요.
6. 배포(푸시)는 제가 "올려"라고 할 때만 하세요.

## 1. 디자인 토큰 (그대로 가져다 쓰세요)
```
--bg:#0b0a09;          /* 페이지 배경: 따뜻한 검정 */
--bg-elev:#17140f;     /* 카드·패널 배경 */
--fg:#f5f1ea;          /* 기본 글자: 따뜻한 흰색 */
--fg-muted:#a89a86;    /* 보조 글자 */
--accent:hsl(270,85%,55%);    /* 보라 */
--accent-2:hsl(284,80%,60%);  /* 밝은 보라(자홍 쪽) */
--line:rgba(245,241,234,.14); /* 모든 테두리·구분선 */
color-scheme:dark;
```
- 포인트 그라데이션은 항상 `linear-gradient(100deg, var(--accent), var(--accent-2))` 한 가지만 씁니다(버튼, 활성 메뉴, 강조 글자).
- 성공 `--ok`(초록), 경고 `--warn`(주황), 오류 `--bad`(붉은색)는 상태 표시에만 최소로 씁니다.
- 글꼴: 영문·숫자·라벨 `Space Grotesk`, 한글 본문 `Gothic A1`(굵기 400/500/700/800/900). 한글 줄바꿈은 `word-break:keep-all`, 제목은 `text-wrap:balance`.
- 모서리: 카드 20~24px, 버튼·칩·내비는 완전 둥근 알약(`border-radius:999px`).
- 테두리는 항상 1px `--line`. 그림자는 은은하게(`0 16px 34px -14px rgba(0,0,0,.75)`) 쓰고, 색 있는 그림자는 보라 포인트에만 씁니다.

## 2. 레이아웃 원칙
- **가운데 정렬 한 줄기**: 제목, 설명, 버튼을 가운데에 쌓고 좌우 여백을 넉넉하게 둡니다. 본문 폭은 520~640px, 카드 묶음은 최대 1040px.
- **구역(section)**: 위아래 여백 96px(모바일은 줄이기), 구역 머리말은 `영문 대문자 라벨(eyebrow)` → `큰 제목(clamp 26~38px)` → `회색 한 줄 설명` 순서.
- **영문 대문자 라벨(eyebrow)**: 12px, 글자 간격 .22em, `--accent-2` 색, 양옆에 28px 가는 선. 모든 구역과 카드 위에 붙여 통일감을 줍니다(예: `LOCAL GROWTH PARTNER`, `BLOG SUPPORTER`).
- 제목 크기는 `clamp(34px, 6.4vw, 74px)`처럼 화면에 맞춰 부드럽게 변합니다. 굵기 800, 줄 간격 1.14. 핵심 단어 한두 개만 그라데이션 글자로 강조합니다.
- 정보는 **카드 격자(3열 → 모바일 1열)**로 나누고, 카드마다 번호(`01`) 또는 라벨, 제목, 두세 줄 설명만 둡니다.

## 3. 핵심 컴포넌트
1. **떠 있는 알약 내비게이션(최우선)**: 화면 위에 고정(`position:fixed`)되고 스크롤해도 따라옵니다. 반투명 어두운 배경 + `backdrop-filter:blur(14px)` + 1px 테두리 + 그림자의 둥근 알약. 현재 위치한 구역의 메뉴는 보라 그라데이션 알약으로 채웁니다(스크롤 위치로 자동 변경). 모바일은 로고를 숨기고 메뉴 전부를 가운데 한 줄에 둡니다.
2. **오른쪽 아래 떠 있는 핵심 버튼(CTA)**: 그라데이션 알약 버튼을 **모든 스크롤 위치에서 항상** 보이게 고정합니다. 은은하게 빛나는(맥박) 그림자 애니메이션을 줍니다.
3. **왼쪽 점 내비게이션**: 화면 왼쪽 가운데에 세로로 점 5개와 가는 선. 지금 구역은 빛나는 점, 지나온 구간은 선이 채워집니다. 마우스를 올리면 이름이 나옵니다(모바일은 이름 숨김).
4. **버튼**: 기본(그라데이션 알약), 보조(투명 + 1px 테두리, 올리면 보라색 테두리). 올리면 2px 위로 뜨고 그림자가 짙어집니다.
5. **칩**: 투명 배경, 1px 테두리, 12px 영문 라벨 글꼴의 작은 알약. 대상 업종, 상태, 필터에 씁니다.
6. **카드**: `--bg-elev` 배경, 1px 테두리, 20~24px 모서리. 올리면 4px 떠오르고 테두리가 보라로 바뀝니다. 강조 카드는 오른쪽 위에 흐릿한 보라 빛 번짐(`radial-gradient` + `blur`)을 얹습니다.
7. **상세 보기 오버레이**: 카드를 누르면 화면을 어둡게 덮고 가운데 패널이 올라옵니다(아래에서 위로 이동 + 투명도). 닫기 버튼, 안의 항목은 순서대로 나타납니다.
8. **글자 띠(마키)**: 서비스 키워드가 가로로 천천히 흐르는 줄. 양 끝은 마스크로 흐려지게 합니다.
9. **진행 패널(HUD)**: 작업 중일 때 큰 숫자 %, 가는 진행 막대, `✓` 표시가 들어가는 단계 목록으로 보여줍니다(예: 키워드 분석 → 매장 정보 반영 → 문장 구성). 기다리는 시간을 "일하고 있다"는 느낌으로 바꿔 줍니다.
10. **지표 카드(KPI)**: 큰 숫자 + 작은 회색 라벨. 숫자는 처음 보일 때 0에서 목표까지 올라가는 애니메이션(0.9초, 부드럽게 감속).
11. **탭**: 알약 모양, 활성 탭은 그라데이션 채움, 비활성은 투명 + 테두리.

## 4. 움직임 (절제해서)
- **처음 등장**: 내비 → 라벨 → 제목(단어별 아래서 위로, 간격 .055초) → 칩 → 설명 → 버튼 순으로 차례로 나타납니다(GSAP, `power3.out`).
- **포인트 색 순환(선택)**: 보라 계열에서 48초에 한 바퀴 천천히 색이 도는 효과. 랜딩과 로그인 화면에만 쓰고, 업무 화면에서는 끄세요.
- **3D 배경(선택, 랜딩과 로그인에만)**: Three.js 정이십면체(안쪽 어두운 면 + 바깥 노란 철선 + 흩어진 점)가 천천히 돌고 마우스에 살짝 반응합니다. 화면 가운데를 비우는 방사형 마스크를 씌워 글자를 가리지 않게 합니다. WebGL을 못 쓰면 은은한 보라 번짐으로 대체합니다.
- 올리기(hover) 반응은 모두 `translateY(-2~4px)` + 테두리 색 변화로 통일합니다.
- **반드시** `prefers-reduced-motion` 설정이면 모든 움직임을 끕니다. 터치 기기에서는 마우스 커서 효과를 쓰지 않습니다.

## 5. 글(카피) 톤
- 짧은 단정문과 쉬운 말. "검색했을 때, 가장 먼저 보이게." 같은 한 줄 약속 → 한 줄 근거.
- 과장 없이 "확인한 뒤에" 같은 신뢰 표현. 결과를 보장하는 표현은 쓰지 않습니다.
- 버튼은 행동을 바로 말합니다("1분 자가진단 하기", "무료 상담 신청"). 화살표 `→`를 붙여 이어지는 느낌을 줍니다.
- 한 문단은 두 줄 안쪽, 핵심은 굵게(`font-weight:700`, 색은 `--fg`).

## 6. 반응형·접근성·성능
- 휴대폰(360~390px)에서 먼저 설계하고, 가로 스크롤이 생기지 않게 합니다.
- 글자와 배경의 대비를 유지하고, 키보드 포커스 표시(`outline:2px solid var(--accent-2)`)는 지우지 않고 그대로 둡니다.
- 외부 스크립트(Three.js, GSAP)는 `defer`로 불러오고, 실패해도 화면이 정상으로 보이게 합니다.
- 화면 흔들림(레이아웃 이동)이 없게 이미지·폰트 크기를 미리 확보합니다.

## 7. 릴로에서 아직 시도하지 않았거나 주의할 점
- 색 순환, 3D 배경, 커스텀 커서는 **눈에 띄는 장식**입니다. 하루 종일 쓰는 업무 화면에는 정보 읽기를 방해하니 쓰지 마세요.
- 어두운 배경만 쓰므로 **밝은 테마**는 지원하지 않습니다. 체어그로스에 밝은 테마가 이미 있다면 유지할지 제게 물어보세요.

## 8. 체어그로스 화면 유형별 적용 범위 (조사 후 제안할 때 이 기준으로 나누세요)
| 화면 | 적용 범위 |
|---|---|
| 랜딩/소개/요금 | **전면 적용**: 히어로, 3D 배경, 알약 내비, 점 내비, 떠 있는 CTA, 카드 격자 |
| 로그인/가입 | 가운데 카드 + eyebrow + 그라데이션 버튼. 3D는 은은하게 |
| 대시보드/진단 결과 | 색, 카드, 탭, KPI 숫자 애니메이션, 진행 패널만 적용. **배경 장식과 색 순환은 끄기** |
| 표/폼/설정 | 정보 읽기가 우선. 색·모서리·테두리·버튼만 통일하고 움직임은 최소로 |
| 모바일 하단 탭바가 있는 화면 | 하단 바를 알약 모양 + 흐림 배경으로 통일, 활성 탭은 그라데이션 |

## 9. 처음 보고할 때 포함할 것
1. 화면 목록과 각 화면의 유형(위 8번 기준)
2. 현재 색, 폰트, 모서리 값과 위 토큰의 차이 표
3. 공통 스타일을 한 곳(변수 파일)에서 바꿀 수 있는지, 화면마다 따로 적혀 있는지
4. 위험한 부분(예: 화면마다 중복된 스타일, 임베드된 코드, 빌드 방식)
5. 추천 작업 순서와 단계별 예상 변경 파일

조사가 끝나면 여기서 멈추고 제 답을 기다리세요.
